What works

Tested locally and on the live site. The demo account emails are in the README. On the live site they use a separate password, which Lesego shares privately; the README password only works locally.

Public website

  • Home, Programmes (plus each programme's own page), Impact, Events, News with pagination and articles, Donate, Volunteer, Contact, Privacy, Safeguarding, 404
  • Impact and donation totals come from real data, not typed-in numbers
  • Volunteer and contact forms validate, record POPIA consent, and land in the staff console
  • Donations go through the PayFast sandbox
  • Safeguarding and Contact pages show Childline South Africa (116). The foundation's own line appears automatically once it's set in Azure.
  • Registration numbers and Section 18A tax-certificate offers only appear once the real NPO/PBO numbers are set, so no fake numbers are shown
  • Works on phone and desktop

Staff console (/admin)

  • Overview, Learners, Register, Announcements, Messages, Volunteers, Donations, Safeguarding, Audit log
  • Each role sees only its own sections: programme staff are refused the safeguarding queue and the audit log
  • People: add learners, parents (linked to their children), mentors and, for administrators, staff; issue invite and reset codes. Programme staff can't reset a staff account.
  • Safeguarding queue: only the designated safeguarding lead can see it

Android app (Kotlin)

  • 11 screens: Sign in, Home, Learn, Subject, Progress, Badges, Buddies, Messages, Notifications, Mentees, Check-in
  • A different menu for learners, parents and mentors
  • New: invite-only accounts. Staff add people in the console's People section; each person gets a one-time code and sets their own password in the app ("I have a code from the foundation") or at /activate. A forgotten password works the same way.
  • Mentor check-ins with a concern go straight to the safeguarding lead
  • New: parents can give or decline permission for activities from Home
  • ./gradlew :app:installAzure installs a build that uses the live site; use it for the demo

Data & integrity

  • Consent history keeps every decision. The database refuses to edit or delete one
  • The audit log cannot be changed, even with direct database access
  • If a safeguarding concern can't reach anyone, the API refuses to save it and tells the mentor to phone instead
  • Demo data on the live site: learners, marks, attendance, 9 news posts, donations, resources, and one account per role

What doesn't work yet, or has limits

One email-security tweak for the client

The domain's SPF record still has +a, which now lets Azure's shared address send email as the foundation. In Afrihost's DNS editor, change it to v=spf1 include:spf.aserv.co.za +mx -all. Details are in docs/deployment.md.

The live site holds demo data

Learners, marks, news and donations on the live site are invented, for the presentation. Before the foundation uses it for real, it needs a fresh database. Deleting the demo rows isn't an option, because consent records and the audit log can't be deleted by design.

Some figures on the site are placeholders

These came from our Task 1 prototype, not from the client. The most important is the Donate page's "audited 2025 allocation" (R1 284 000 / R188 000 / R94 000): it's invented but presented as audited. Also placeholders: the "what your gift buys" amounts, the Volunteer page's "most needed" counts, the main phone +27 71 000 0000 and the Cornwallis Street address. The home and Impact statistics are calculated live, but from demo data.

The domain may show the old page for a while

DNS changes take up to 2 hours to reach every network. Until then some people still see Afrihost's "Domain Registered" page. www.theebuhlefoundation.co.za and theebuhle-foundation.azurewebsites.net already work everywhere. This fixes itself.

CI/CD has never run

The workflow files exist, but GitHub has never run them. Expect small fixes on the first push, such as missing secrets or path differences.

Payments are sandbox only

PayFast works with PayFast's public test account. Real donations need the client's merchant ID, key and passphrase.

Emails aren't sent

Email settings are empty until the client provides their Afrihost SMTP details.

Two app features need a run-through on the live site

Nobody has yet (1) signed in to the app on the live data as parent, mentor and learner, or (2) tapped through the parent consent dialog and the new "I have a code" screen end to end. The automated tests cover the server side; this is about the phone.

The free database has a monthly limit

It pauses after an hour with no visitors, and it only gets about 55 hours awake a month. If that runs out, it stays paused, and the site is down until the next month. That's plenty for marking and the presentation, but don't leave the site open and refreshing. Open it 5 minutes before a demo so it has time to wake up. Check what's left: Azure portal → theebuhle database → Metrics → "Free amount remaining".
